# R2 — художественное ревью Opus: что сдавать и как принимаю

**Authority:** [FINAL GATE R-A AUTHORIZATION](GATE_R_A_AUTHORIZATION.md). Художественная заморозка — **`9cf78b0`** (ветка `docs/0524-w4-ad-opus-art-direction`). Реализация — Sol в PR #12 (`w4/world-narrative`). Этот протокол задаёт планку заранее, чтобы стадия сдавалась один раз.

Ревью Opus — художественное: верность A+AD и отсутствие упрощений. Оно не заменяет независимые R3/R4 и не даёт Gate B.

## 0. Перед R2.1 (рекомендация)

`docs/0524-w4-ad-opus-art-direction` построена прямо на `895b7cf`, поэтому `w4/world-narrative` можно перемотать вперёд (fast-forward) до неё без конфликтов. Тогда эталон A+AD (`evidence/w4ad/`), решения и этот протокол окажутся в PR #12 рядом с реализацией. Решение за Sol/Principal: Opus PR #12 не пишет. Эталон A+AD в любом случае — дерево `9cf78b0`. Последующие коммиты ветки Opus — только документы: `git diff 9cf78b0..<tip> -- docs/showcase-v031/evidence/w4ad/preview docs/showcase-v031/evidence/w4ad/captures` пуст.

## 1. Что сдаёт Sol на каждую стадию

1. Запушенный **implementation SHA** и список изменённых продуктовых файлов (`git diff b85fbb0a --stat -- index.html assets tests`).
2. **Нативные кадры IMPLEMENTED** секций стадии: 1440×900, 390×844, 360×800 (для доктрины ещё 1920×1080). Состояния — как у эталона: DPR 1, `reducedMotion: reduce`, флаг возвращающегося посетителя, gallery 01, map 02.01. Для лент — кадр каждой карточки на 390. Эталонные кадры A+AD уже лежат в `evidence/w4ad/captures/`.
3. **Высоты секций** в четырёх viewport и **результаты проверок стадии**: no-JS / клавиатура / touch, где это применимо.
4. **Список отклонений** от A+AD, каждое с причиной. Пустой список — тоже ответ.

## 2. Как принимаю

- **Текст.** Нормализованный текст секций стадии в IMPLEMENTED совпадает с `ad.html` из `9cf78b0`, то есть со строками `build_ad.py`. Ни одной «улучшенной» формулировки без решения Opus.
- **Графика.** `d`-атрибуты SVG кольца фрагментации, объекта зависимости и четырёх модулей совпадают с `ad.html`.
- **Геометрия.** Высота каждой секции стадии отличается от эталона не больше чем на **±1 % или ±16 px** (что больше) в каждом viewport (таблица ниже). Больше — объясняется и показывается в кадрах.
- **Protected.** Карта, оси, OMEGA-0, карточки персонажей, AXIOM ∅, viewer, восемь `ax-shot` / `ax-case`, SYSTEM — побайтно как в `b85fbb0a`.
- **Глаз.** Сравниваю кадры IMPLEMENTED с эталонными A+AD при одинаковой ширине: композиция, иерархия, свет, пустоты. Чисел недостаточно — смотрю каждый кадр.

## 3. Критерии по стадиям

### R2.1 — BLACK SUN / WHAT REMAINS

Обязательно присутствует:
- Три зоны архива 236 / 248 px при ширине > 1100. У терминала нет `min-height`.
- Кольцо фрагментации: пять дуг, CONTROL залит и зажат двумя скобами, центр `∅`. Строка состояния: `01 ФРАГМЕНТИРОВАН · 02 НЕ СТЁРТ · 03 НЕ ВОССТАНОВЛЕН`. Figcaption с фразой о канонической модели фрагментации.
- «Пять следов. Одно имя.»: пять исходных рам с глифами, подвалы `ВСТРЕЧАЕТ / ПРИНИМАЕТ ЗА`. У BIO — пунктирная рамка и подвал `РЕЖИМ / СКРЫТОЕ ПРИСУТСТВИЕ`. На десктопе 5 колонок, ≤ 760 px — snap-лента с `← NN / 05 →`.
- AFTERMATH. Порог A08 через `<picture>`: AVIF + WebP 480/720/941w (хэши = `proposed-assets/derivatives.json`), `sizes` как в эталоне, сканирующая линия через центр ворот (26,4 % на десктопе / 38,8 % на мобильном). Память — W02, 520 px. Зависимость — отдельная строка на всю ширину; в обычном режиме по пульсу бежит свет, в RM — нет. W04 только в WORLD.
- На 390 кольцо стоит рядом со строкой состояния, а не под ней.

Не принимается: аккордеон или скрытие следов; удаление кольца, строки состояния или глифов; возврат W04 в «допуск» или замена A08; перенос зависимости во вторую колонку; иные формулировки.

### R2.2 — WORK / FOUR SURFACES

- Реальный архив (8 figures/cases, viewer) — как в `b85fbb0a`. Три упрощённых disclosure 02/03/05 убраны. Экспозиция стоит после viewer и перед `#work-intro`.
- Шапка: `SURFACE STUDIES / ЭТЮДЫ ИНТЕРФЕЙСОВ`, «ЭТЮДЫ / ВИЗУАЛЬНОГО ЯЗЫКА.», вводная со «снимками реальных интерфейсов проекта» и передачей к SYSTEM. Четыре текста модулей и короткая заметка — как в эталоне.
- Модули: исходная SVG-геометрия, рамки, углы, подвалы с условными метками, без статусов и версий. Индекс из четырёх якорей.
- ≤ 760 px: лента 90 %, карточки одинаковой высоты (подвал прижат вниз), без побуквенного переноса в подвалах, `← NN / 04 →`. Без JS индекс работает как якоря, лента прокручивается нативно. Клавиатура и touch доходят до последнего модуля.
- SYSTEM не меняется.

Не принимается: свёрнутые модули, второй архив скриншотов, возврат слов «система» и «четыре» в шапку экспозиции, возврат перечня осей в CARTOGRAPHY.

### R2.3 — WORLD GRID / CHARACTERS

- `THE CITY RISES. / THE DEPTH IS SEALED.` + «Город растёт вверх. Глубина закрыта.» — точная строка, одна строка в рамке W04 на 390 и 360.
- Вводная о шести узлах между двумя полюсами — дословно. Вторая вводная с осями — без изменений.
- `THREE LIVES / INSIDE THE FRACTURE.` + «Три жизни внутри разлома». Последняя фраза вводной: «На карте порядок выглядит как схема. В их судьбах — как цена.» При ширине ≤ 380 заголовок 34 px.
- Рамка W04, карта, OMEGA-0, портреты, биографии, AXIOM ∅ — exact.

## 4. Отклонения

Если реализация требует отклонения, Sol останавливает это изменение и присылает: что, почему (техническая причина), кадры A+AD и предлагаемого варианта. Opus отвечает записью решения: принять, изменить или отклонить, — в `waves/w4ad/OPUS_DECISIONS.md`. Технические правки без художественного эффекта (порядок CSS, сведение `r1p.css` + `ad.css`, имена файлов ассетов) допустимы без запроса, с регрессионной проверкой высот и кадров.

## 5. Запись ревью

На каждую стадию — `waves/w4ad/OPUS_REVIEW_R2_1.md`, `…_R2_2.md`, `…_R2_3.md`:

```text
OPUS ART REVIEW R2.x — PASS | CHANGES REQUESTED
Implementation SHA: <sha>   Art baseline: 9cf78b0
Checked: text / SVG / geometry (4 viewports) / protected / frames (list)
Deviations: <none | list with decision>
Required changes: <none | list>
Not an R3/R4 verdict; Gate B remains CREATOR.
```

Следующая стадия начинается только после PASS предыдущей.
