## 2. Срезы

Порядок: **W3.A → W3.B → W3.C → W3.D**. Изменения сериализуются, потому что все срезы пишут в `index.html` и общий каскад CSS (A-GLB-01: 4 слоя `index` → `showcase` → `v22` → `v23`). Исследование и A/B-макеты для следующих срезов можно готовить параллельно, только чтением.

### W3.A — Фундамент + HERO / ABOUT / CREATOR

**Проблемы:** B-GLB-01 (плавающая метка), B-GLB-02 (CTA и первый экран на коротких окнах), B-GLB-03 (хром в ландшафте), B-GLB-05 (порог микротекста — токены), B-GLB-07 (полускрытые bridge-заголовки при переходе по якорю), B-HERO-01…05, B-ABOUT-01, B-CRE-01.

**Направления (A/B — на решение CREATOR):**
1. Плавающая метка секции: **A** скрыть до ≤ 900 px (активный пункт уже подсвечен в липкой мобильной навигации); **B** встроить тонким индикатором в мобильную навигацию; **C** оставить, но в безопасной зоне, с автоскрытием при прокрутке. Рекомендация агента: A (минимальный риск).
2. HERO на коротких окнах: высота заголовка ограничивается и по высоте окна (`min(vw, vh)` в `clamp`); три яруса под CTA сводятся к двум — CTA с подписью статуса и строка быстрого перехода. Строку `CREATOR / ENDEAVOR · DESIGN / CODE / CANON` не удалять: перенести в существующий ряд или в рамку (вариант — CREATOR).
3. Телефон: подпись-«бровь» в одну строку (короче трекинг) или две ровные строки; быстрый переход без «сироты» (3 в ряд на ≥ 360 или 1+2 намеренно); компактный радар как «объект» первого экрана — только вариантом A/B (CREATOR).
4. Ландшафт телефона: липкий хром (логотип + тикер + навигация) не более 22 % высоты, тикер сворачивается при прокрутке.
5. Токены микротекста: смысловые подписи ≥ 11 px desktop / 12 px телефон, трекинг ≤ 0,2 em у подписей ≥ 11 px; HUD-декор остаётся как есть и помечается `aria-hidden`, где ещё не помечен.
6. Роль шрифта для прозы HERO (lede и описания features — сейчас JetBrains Mono): **A** оставить моно (голос терминала); **B** Golos Text, как в ABOUT. Решение CREATOR — роли TYPE A не меняются молча.

**Владение файлами:** `index.html` (только `#top`, `#about`, `#creator`, header/nav и `.v22-current-label`), `assets/css/showcase-v22.css`, `assets/css/showcase-v23.css` (селекторы этих зон), `assets/js/showcase-v22.js` (метка). Остальные зоны — только чтение.

**DoD:** цели §1 по строкам «метка», «CTA», «хром»; HERO-радар, геометрия и композиция сохранены (сравнение 1440/390 до и после); `w3-preserve` — текст без изменений, кроме одобренных; регрессия + новые проверки R-W3A-*; LH не хуже цели.

### W3.B — WORK / SYSTEM: доказательство как экспозиция

**Проблемы:** B-WORK-01 (превью ≈ 55 % ширины, детали UI не читаются), B-WORK-02 (карточка WEB CORE как приложение; ссылка 14 px), B-A01-01 (подпись концепт-арта), B-SYS-01 (архитектура — сетки карточек; A07 рядом с пустой половиной), B-SYS-03 (дубль навигации к лору).

**Направления:**
1. Архив: превью не меньше 60–65 % ширины на ≥ 1280; на ≤ 1100 кейс под превью; на телефоне детали кейса сворачиваются. Каждый экран по-прежнему один раз (WORK B).
2. Карточка AXIOM WEB CORE — как «публичный маршрут» рядом с архивом или в его шапке, а не после него; цель касания ≥ 44 px.
3. SYSTEM: четыре опоры и поток CANON → MASTER GRAPH → WEB CORE → AXCHAT — **одна схема** (CSS/SVG, без новых изображений) вместо двух сеток карточек; A07 — полноширинная полоса или пара к схеме.
4. Дубль навигации к лору: оставить путь WORLD-гида, в SYSTEM — одну ссылку. Это изменение IA, решает CREATOR.
5. Подпись A01: пометить как арт («концепт», «атмосфера»), если CREATOR согласен (W5-редактура; в W3 — только с разрешения).

**Владение:** `index.html` (`#work-art-band`, `#work`, `#system`), `showcase-v23.css`, `showcase-gallery.js` (без изменения логики просмотрщика), `showcase-v23.js` (поток SYSTEM).

**DoD:** просмотрщик FIT/1:1, вкладки, фокус, свайп — без регрессий (R38/R39 и связанные); резкость не ниже базы `sharpness`; ни одного нового изображения; preservation текста.

### W3.C — WORLD / MANIFESTO / MODULES / КАРТА / ENTITIES / AXIOM ∅ / FACTIONS

**Проблемы:** B-MOD-01 (коллизия подписи карты), B-MOD-02 (лог пингов на телефоне), B-MOD-03 (выравнивание шапок карточек), B-MAP-01 (перенос «OMEGA-/0», стрелка ↗ в Arial), B-MAP-02 (превью карты на телефоне), B-ENT-01 (ENTITIES ≈ 6 экранов на 390), B-AXM-01 (обрезка HUD-текста портрета), B-AXM-02 (плотная проза в моно), B-GLB-06 (нумерация `// 01–05`).

## 3. Распределение агентов (предложение)

По умолчанию протокола: 1 Lead + 1 реализатор + 1 QA, не больше трёх одновременно. Пишет в продукт только один агент. Остальные работают на чтение или в одноразовом браузерном контексте.

| Роль | Кто | Что делает | Чего не делает |
| --- | --- | --- | --- |
| Lead / Integrator | CODEX (текущий агент) | SPEC-дополнение среза, точный базовый HEAD, доска задач, интеграция ветки среза, повтор W3.0-замеров, evidence, handoff | не утверждает вкус; не проверяет сам свой код как независимый ревьюер |
| Visual Lead | отдельный агент (frontend-developer, только чтение) | A/B-макеты: CSS-оверрайды в одноразовом контексте Playwright → снимки 1440/390, без записи в репозиторий | не пишет в ветки; не меняет палитру, шрифты и порядок |
| Frontend Implementer | один агент на срез | реализация одобренного варианта: малые атомарные коммиты в `w3/<slice>` | не трогает чужие зоны, `main`, Canon, корень AXS |
| QA / Accessibility | независимый агент (не автор среза) | `w3-audit`, `w3-preserve`, `w3-focus`, регрессия, axe, Lighthouse, Firefox; попытки сломать (коллизии, фокус, reduced motion, lite) | не ставит PASS вместо NOT RUN |
| Editorial / Canon | только по запросу, только чтение | если срез затрагивает текст — матрица источников и уровни истины | не публикует DRAFT как CANON; не расширяет BLACK PROTOCOL/Стирание |
| Principal | AXIOM Principal | раздельные вердикты: технический и визуальный по срезу; gate-record перед merge | не одобряет свои коммиты |
| CREATOR | CREATOR | A/B-решения, роли шрифтов, IA, финальная визуальная приёмка | — |

**Параллельно (только чтение):** макеты W3.B/W3.C готовятся, пока реализуется W3.A. **Последовательно (запись):** A → B → C → D; следующий срез стартует от HEAD, в который влит предыдущий, и только после его приёмки.

## 4. Цикл среза

`SPEC-дополнение (стартовый SHA, файлы, A/B)` → `макеты A/B` → `решение CREATOR` → `реализация в w3/<slice>` → `QA (полный набор W3.0 на точном SHA)` → `Principal: технический + визуальный вердикт` → `gate-record: AUTHOR/REVIEWER, REVIEWED SHA, QA SHA, verdict, allowed target = feature, authority` → `merge в feature` → `post-merge: регрессия + атлас + preservation` → `handoff`.

Gate-record обязателен перед **каждым** merge (правило 0524.CLOSURE-R1). Нет записи или запись не для текущего HEAD — merge запрещён.
