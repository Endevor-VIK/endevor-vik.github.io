### P2-1 — Публикация доказательств через GitHub Pages; аудит размера устарел; локальные пути в доказательствах
- **Факт:** `git diff --name-status 6b082e5 3dd6cef` → 1 931 A + 6 M = 1 937 файлов, 87,18 МиБ, из них `docs/showcase-v031/evidence/**` 85,65 МиБ. `R3_PR_SIZE_AUDIT.md` говорит о 1 778 / 78,3 МиБ (подсчёт на `914caae`). В репозитории нет `_config.yml`/исключений, поэтому после merge всё дерево `docs/` будет доступно по URL сайта.
- В 37 текстовых файлах доказательств есть абсолютные пути хоста (`/home/axiom/...`, `/tmp/claude-1000/...`). Это раскрывает имя пользователя и раскладку WSL. Секретов не найдено.
- **Воспроизведение:** `git diff --name-only 6b082e5 3dd6cef | grep -vE '\.(webp|png|jpg|avif|zip|woff2)$' | xargs grep -l -E '/home/axiom|/tmp/claude-1000' | wc -l` → 37.
- **Влияние:** runtime не затронут. Это решение уровня merge/Gate B, и оно уже вынесено исполнителем на CREATOR. До merge нужно выбрать вариант размещения доказательств и обновить цифры аудита. Вариант 1 из аудита (неизменяемая ссылка + перенос в `main` только продукта) снимает и проблему путей.

### P3-1 — D-06: при отдельной задержке `showcase-w4r.css` прямая ссылка на секцию промахивается
- **Воспроизведение:** `tools/r4_probe.cjs --part deeplink`. Локальный сервер задерживает только `showcase-w4r.css` на 2 с, затем открываются `/#manifesto` и `/#modules`. Итог: CLS 0,96 на 390 px и 0,44 на 1440 px; цель после применения стиля стоит на −869 / −1619 px (390) и +240 px (1440 `#manifesto`). Без задержки (0 мс) и при реалистичном троттлинге всех ресурсов (п. 4.5) промаха нет, цель на месте.
- **Причина:** асинхронный стиль меняет высоты секций над целью после того, как браузер уже прокрутил к якорю. До D-06 стиль блокировал отрисовку, и такого окна не было.
- **Влияние:** только редкая ситуация, когда маленький стиль (6 КБ gzip) приходит заметно позже остальных. Обычная загрузка без хэша не затронута. Исправление до публикации не требуется. Если CREATOR захочет закрыть риск, есть вариант с новым SHA: после `onload` повторно вызвать `location.hash`-скролл, если в URL есть якорь. Ещё одно замечание: D-06 опирается на inline-обработчик `onload`. Если на сайт когда-нибудь добавят CSP без `'unsafe-inline'`, у пользователей с JS стиль останется `media=print`. Сейчас CSP нет (GitHub Pages, мета-CSP отсутствует).

### P3-2 — Firefox: клавиатура в ленте следов делает «пустые» нажатия
- **Воспроизведение:** `tools/r4_ff_traces.cjs` → `evidence/r4-firefox-traces-keyboard.json`. На 390 px (с JS и без, с RM и без, ожидание 500 и 1500 мс) `scrollLeft` после каждого ArrowRight такой: `0,316,316,632,632,948,948,1206` — каждое второе нажатие ничего не сдвигает. На 400/412/430/375 px картина похожая (с пропусками), на 360 px шаги ровные. Chromium и WebKit делают шаг на каждое нажатие (кроме P3-3).
- **Влияние:** все пять карточек достижимы с клавиатуры (крайняя позиция достигается за ~7 нажатий), фокус есть, с JS есть кнопки ← →. Это неудобство, а не потеря доступа; поведение задаёт нативный mandatory snap Firefox в разметке A+AD. Матрица исполнителя этого не видит: она нажимает n+2 раз и затем докручивает `scrollBy` (см. P3-5). Записать как ограничение; не блокирует.
